# 要件: blocklist-ui

## 目的

ブロックリストは保存領域に移った（`blocklist-storage`）が、変える手段が開発者向けのコンソールしかない。
利用者が拡張の画面からサイトを追加・削除でき、追加したサイトがその場でブロックされるようにする。これで第一段階を手元の Chrome で使える状態にする。

## 要件

### 1. 一覧

- **1.1** 利用者がツールバーの拡張のアイコンから編集画面を開いたとき、システムは保存されているブロックリストのサイトを保存順にすべて表示しなければならない
- **1.2** 保存されているブロックリストが空のとき、システムはサイトが1件もないことを表示しなければならない
- **1.3** 編集画面を開いている間に別の場所でブロックリストが変わったとき、システムは開き直さずに表示を最新の保存内容にしなければならない
- **1.4** 拡張がブロックに必要な権限を持たないサイトがあるとき、システムはそのサイトがブロックされていないことを、そのサイトの行に表示しなければならない
- **1.5** 保存内容にドメインとして扱えない項目があるとき、システムはその項目を無効であると分かる形で表示し、削除できなければならない

### 2. 追加

- **2.1** 利用者がドメイン（例: `youtube.com`）を入力して追加したとき、システムはそのサイトへの権限を利用者に求め、許可されたらブロックリストの末尾に保存しなければならない
- **2.2** 2.1 で保存したとき、システムは拡張の更新・再読み込みなしに、その後に開いたそのサイト（サブドメインを含む）をブロックしなければならない
- **2.3** 利用者が権限の許可を拒否したとき、システムはブロックリストを変えず、ブロックできないため追加しなかったことを表示しなければならない
- **2.4** 入力に大文字が含まれるとき、システムは小文字にしてから扱わなければならない
- **2.5** 入力が URL（例: `https://www.youtube.com/watch?v=1`）のとき、システムはそのホスト名を取り出して扱わなければならない
- **2.6** 2.5 のホスト名または入力が `www.` で始まるとき、システムは `www.` を外して扱わなければならない（`www.youtube.com` → `youtube.com`）
- **2.7** 前後の空白を除いた入力が空、またはドメインとして扱えないとき、システムは保存せず、理由を表示しなければならない
- **2.8** 入力したサイトが既にブロックリストのサイトそのもの、またはそのサブドメインのとき、システムは保存せず、既にブロックされていることを表示しなければならない
- **2.9** ブロックリストが登録できる上限（1,000 件）に達しているとき、システムは保存せず、上限に達したことを表示しなければならない

### 3. 削除

- **3.1** 利用者があるサイトを削除したとき、システムはそのサイトだけをブロックリストから外して保存しなければならない
- **3.2** 3.1 で保存したとき、システムは拡張の更新・再読み込みなしに、その後に開いたそのサイトをブロックしてはならない
- **3.3** 利用者が最後の1件を削除したとき、システムは空のブロックリストを保存しなければならない（初期値に戻してはならない）
- **3.4** 3.1 で削除したサイトの権限を 2.1 で得ていたとき、システムはその権限を手放さなければならない。インストール時から持つ権限（初期値のサイト）は手放せないので対象外とする

### 4. 権限

- **4.1** システムは、インストール時に利用者に表示される権限の説明を `blocklist-storage` から変えてはならない
- **4.2** システムは、利用者が追加しようとしたサイト以外への権限を、追加の操作の中で求めてはならない

### 5. 回帰

- **5.1** 1.1〜1.5・2.x・3.1〜3.3 は、実装を壊したときに失敗する自動テストで確認できなければならない。ただし権限の許可・拒否の操作そのものは自動化できない場合に限り目視とする
- **5.2** 5.1 の自動テストは、ブロックリストのサイトや公開中のブロック画面へ実際に接続せずに通らなければならない

## 範囲外

- 時間帯・曜日によるブロック — `schedule-blocking`（#12）
- 一時解除 — `temporary-unblock-extension`（#14）・`temporary-unblock-page`（#15）
- ブロックリストの並べ替え・一括の追加・書き出しと読み込み — 必要になった時点で別の機能にする
- パス単位のブロック（`youtube.com/shorts` だけ止める など） — ルールの組み立て（`redirect-rules`）の変更が要るため
- 見た目の作り込み（テーマ・アイコン・多言語化） — 第一段階では機能が使えることを優先する
- Chrome ウェブストアでの公開 — `store-release`（#17）

なし（以下は決定済み）

| 論点 | 決め方 |
| ---- | ------ |
| U1: 編集画面をどこに置くか | **決定: ツールバーのアイコンから開くポップアップ**（1.1） |
| U2: `www.` で始まるホスト名を `www.` を外して保存するか | **決定: 外す**（2.6）。`youtube.com` 全体がブロックされる |
| U3: 削除したサイトの、追加時に得た権限を手放すか | **決定: 手放す**（3.4）。再び追加するときはもう一度許可を求める |
