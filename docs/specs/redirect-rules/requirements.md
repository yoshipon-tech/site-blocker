# 要件: redirect-rules

## 目的

自分で決めたサイトを開いたとき、ページが表示される前に止めたい。現状の拡張は雛形のみで、何も止めない。
コードに書いたブロックリストのサイトを開くと、`blocked-page` で公開したブロック画面へ元URL付きで移るようにし、MVP（「x.com を開くとブロック画面が出る」）を完成させる。

## 要件

### 1. ブロック

- **1.1** ブロックリストのサイトの URL をタブで開いたとき（アドレスバーへの入力・リンク・ブックマーク）、システムは元のページを表示せずにブロック画面へ遷移させなければならない
- **1.2** ブロックリストのサイトのサブドメイン（`www.x.com`、`mobile.x.com` など）を開いたときも、システムは 1.1 と同じくブロックしなければならない（U1）
- **1.3** ブロックリストにないサイト（`example.com`、名前が似ているだけの `notx.com`、`x.com.example.test` など）を開いたとき、システムはブロックしてはならない
- **1.4** ブロックリストにないページが、ブロックリストのサイトの画像・スクリプト・iframe を読み込むとき、システムはそれらをブロック画面へ遷移させてはならない
- **1.5** `http` と `https` のどちらで開いたときも、システムは 1.1 と同じくブロックしなければならない
- **1.6** ブロックしたとき、システムはブロックリストのサイトのサーバーへリクエストを送ってはならない

### 2. 元URLの受け渡し

- **2.1** ブロックしたとき、システムは `https://yoshipon-tech.github.io/site-blocker/blocked/#<元URL>`（`guide-tech.md` の URL の契約）へ遷移させなければならない
- **2.2** 元URLにパス・クエリ（`?` `&` `=` を含む）があるとき、システムはそれらを欠かさず、エンコードし直さずに `#` の後ろへ置かなければならない
- **2.3** 元URLにフラグメント（`#` 以降）があるとき、システムはフラグメントも含めて引き継がなければならない（U4。判定に渡る URL にフラグメントが含まれることを実ブラウザで確認した）

### 3. ブロックリストの登録

- **3.0** ブロックリストは、コードに書いた `x.com` と `twitter.com` でなければならない（U2）。変えるときは開発者がコードを書き換えて拡張を更新する
- **3.1** 拡張をインストールしたとき、システムはブロックリストの全サイトをブロックする状態にしなければならない
- **3.2** ブラウザを再起動したあとも、システムは 3.1 の状態を保たなければならない
- **3.3** ブロックリストを変えた拡張に更新・再読み込みしたとき、システムは新しいリストどおりにブロックし、リストから外したサイトをブロックしてはならない
- **3.4** インストール・更新・再起動を何度繰り返しても、システムは同じサイトに対するブロックを重複して持ってはならない

### 4. 権限

- **4.1** インストール時にユーザーへ表示される権限の説明は、ブロックリストのサイト（とそのサブドメイン）に限った内容でなければならず、すべてのサイトへのアクセスを求めてはならない（U3）

### 5. 開発

- **5.1** 開発者が開発用のコマンドを実行したとき、システムは拡張を読み込んだ Chrome を起動し、ソースの変更を再ビルドして反映しなければならない

### 6. 回帰

- **6.1** 1.1〜1.5 と 2.x は、実装を壊したときに失敗する自動テストで確認できなければならない
- **6.2** 6.1 の自動テストは、ブロックリストのサイトや公開中のブロック画面へ実際に接続せずに通らなければならない

## 範囲外

- 利用者がブロックリストにサイトを追加・削除すること（編集 UI・storage への保存・追加したサイトの権限の要求） — `blocklist-storage`（#10）、`blocklist-ui`（#11）
- 時間帯・曜日によるブロック、一時解除 — #12、#14
- ブロック画面の表示 — `blocked-page`（公開済み）
- Chrome ウェブストアへの公開・権限の説明文 — `store-release`（#17）
- Chrome 以外のブラウザ — 第一段階は Chrome の開発者モードで使う（`guide-product.md`）
- シークレットウィンドウでの動作 — 拡張の設定で人が許可するもので、この機能では扱わない

## 未決事項

なし（U1: サブドメインも含める → 1.2、U2: `x.com` と `twitter.com` → 3.0、U3: ブロックリストのサイトだけ → 4.1、U4: 判定に渡る URL にフラグメントがなければ引き継がない。実ブラウザで含まれると確認したので引き継ぐ → 2.3 で決定）
