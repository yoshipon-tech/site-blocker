# 要件: blocked-page

## 目的

拡張がリダイレクトした先に、何が止められたかを伝える画面が要る。現状は `apps/web` が雛形のままで公開もされていない。
この機能で、URL の契約（`/site-blocker/blocked/#<元URL>`）どおりに開ける画面を公開し、拡張の実装と検証の受け皿にする。

## 要件

### 1. 元URLの表示

- **1.1** フラグメントが空でない URL でブロック画面を開いたとき、システムはフラグメントの先頭 `#` を除いた文字列を元URLとして画面に表示し、そのホスト名（先頭の `www.` を除く）を「<ホスト名> は今ブロックしています」の形で表示しなければならない
- **1.2** 元URL自体に `#` が含まれるとき、システムは最初の `#` 以降をすべて元URLとして表示しなければならない（例: `#https://example.com/a#b` → `https://example.com/a#b`）
- **1.3** 元URLに `<` `>` `"` などの記号が含まれるとき、システムはそれらを文字として表示し、要素やスクリプトとして解釈してはならない
- **1.4** 元URLを表示するとき、システムは元URLをクリックで遷移できるリンクにしてはならない
- **1.5** ブロック画面を開いたとき、システムは見出し「いまは、目の前のことに。」を表示しなければならない
- **1.6** 表示後にフラグメントだけが変わったとき、システムは表示中の元URLを新しいフラグメントに合わせて更新しなければならない
- **1.7** 元URLがパーセントエンコードされているとき、システムはデコードして表示しなければならない。ただし URL の区切りを表す文字（`%26` `%2F` など）は戻さず、デコードに失敗したときは届いたまま表示しなければならない
- **1.8** 戻れる履歴があるとき、システムは「前のページに戻る」ボタンを表示し、押されたら1つ前の履歴に戻らなければならない
- **1.9** 元URLがホスト名を持つ URL として解釈できないとき、システムはホスト名の代わりに元URLをそのまま表示しなければならない

### 2. フラグメントが空のとき

- **2.1** フラグメントなし、または `#` のみでブロック画面を開いたとき、システムは元URL欄を表示せず、このページが拡張のブロック画面であることを説明する文を表示しなければならない

### 3. 外部に送らない

- **3.1** ブロック画面を開いたとき、システムは元URLを含むリクエストを一切送信してはならない
- **3.2** ブロック画面を開いたとき、システムはブロック画面と同じオリジン以外へリクエストを送信してはならない

### 4. 公開

- **4.1** main ブランチのブロック画面のコードが更新されたとき、システムは人の操作なしにブロック画面を `https://yoshipon-tech.github.io/site-blocker/blocked/` に公開しなければならない
- **4.2** 公開されたブロック画面を `/site-blocker/blocked/`（末尾スラッシュ付き）で開いたとき、システムはリダイレクトを挟まずに画面を返さなければならない
- **4.3** 公開されたブロック画面を開いたとき、システムは画面が参照するスクリプト・スタイルをすべて読み込めなければならない（404 が出ない）
- **4.4** ビルドまたはテストが失敗したとき、システムは公開を行わず、公開中の画面を置き換えてはならない
- **4.5** 開発者が手動で公開を実行したとき、システムは main の内容でブロック画面を公開しなければならない

## 範囲外

- ブロックの判定とリダイレクト — `redirect-rules`
- ルート（`/site-blocker/`）に置くページ（プライバシーポリシーなど） — 公開準備の段階で別機能にする
- 一時解除（「5分だけ開く」）やブロックリスト編集への導線 — 次段階以降
- カスタムドメイン — 公開前に判断する（`guide-tech.md`）
- 解除までのカウントダウン表示 — 時間帯ブロック（次段階以降）で解除時刻が決まるまで、表示する値がない
- ダークモード、多言語対応 — 次段階以降
- プルリク時にビルド・テストを走らせる CI — `monorepo-setup` でも範囲外にした。公開ワークフロー内でのビルド・テストのみ行う
