# 要件: blocklist-storage

## 目的

いまのブロックリストはコードに書いた定数で、変えるには拡張を書き換えて更新するしかない。
ブロックリストを拡張の保存領域に置き、保存内容が変わったら再ビルドなしにブロックが追従するようにする。編集 UI（#11）・時間帯（#12）・一時解除（#14）が載る土台にする。

## 要件

### 1. 初期状態と保存

- **1.1** 拡張を初めてインストールしたとき、システムは `x.com` と `twitter.com` をブロックリストとして保存し、それらをブロックしなければならない
- **1.2** コードに書いたブロックリストで動いていた版（`redirect-rules`）から更新したとき、システムは 1.1 と同じ状態にしなければならない
- **1.3** 保存済みのブロックリストがあるとき、拡張の更新・再読み込み・ブラウザの再起動のあとも、システムは保存内容を初期値で上書きしてはならない
- **1.4** 保存済みのブロックリストが空のとき、システムはそれを初期値で埋め直してはならず、どのサイトもブロックしてはならない

### 2. 保存内容への追従

- **2.1** 保存されたブロックリストからサイトを外したとき、システムは拡張の更新・再読み込みなしに、その後に開いたそのサイトをブロックしてはならない
- **2.2** 保存されたブロックリストにサイトを足したとき、そのサイトへの権限を拡張が持っていれば、システムは拡張の更新・再読み込みなしに、その後に開いたそのサイトをブロックしなければならない（U2）
- **2.3** 保存内容が何度変わっても、システムは同じサイトに対するブロックを重複して持ってはならず、保存内容にないサイトのブロックを残してはならない
- **2.4** ブラウザを起動したとき、システムはブロックの状態を保存されたブロックリストと一致させなければならない（前回の終了前に追従が終わっていなかった場合を含む）
- **2.5** 同じサイトがブロックリストに2回以上あるとき、システムはそれを1サイトとしてブロックしなければならない
- **2.6** 拡張が権限を持たないサイトがブロックリストにあっても、システムは権限を持つ残りのサイトを 1.x・2.1〜2.5 どおりにブロックしなければならない（U2）

### 3. 不正な保存内容

- **3.1** ブロックリストにドメインとして扱えない項目（空文字、スキームやパスを含む文字列、大文字を含む文字列など）があるとき、システムはその項目を無視し、残りの項目は 1.x・2.x どおりにブロックしなければならない
- **3.2** 3.1 で項目を無視したとき、システムは無視した項目と理由を、開発者が拡張の service worker のコンソールで確認できる形で残さなければならない
- **3.3** 保存内容がブロックリストとして読めない形（リストでない値など）のとき、システムはどのサイトもブロックせず、3.2 と同じく理由を残さなければならない

### 4. 既存の要件の維持

- **4.1** `redirect-rules` の要件 1.x（ブロックする範囲としない範囲）・2.x（元URLの受け渡し）・4.1（権限の説明）は、ブロックリストが保存領域から来る場合も満たさなければならない

### 5. 回帰

- **5.1** 1.x・2.1〜2.3・2.5・2.6・3.1・3.3 は、実装を壊したときに失敗する自動テストで確認できなければならない
- **5.2** 5.1 の自動テストは、ブロックリストのサイトや公開中のブロック画面へ実際に接続せずに通らなければならない

## 範囲外

- 利用者がブロックリストを編集する画面と、入力値の正規化（大文字→小文字、URL からのドメイン抽出など） — `blocklist-ui`（#11）
- 足したサイトへの権限を利用者に求めること — `blocklist-ui`（#11）。この機能では権限を `x.com`・`twitter.com` のまま変えない（U2）
- 時間帯・曜日によるブロック、一時解除 — #12、#14（この機能はそれらが載せられる保存の形を用意するところまで）
- 登録できるルール数の上限を超えたときの扱い — `blocklist-ui`（#11）で入力時に制限する
- 同じ Google アカウントの別の端末への同期 — しない。ブロックリストはその端末の Chrome にだけ保存する（U1）
- ブロックリストの書き出し・読み込み — 必要になった時点で別の機能にする

## 未決事項

なし（以下は決定済み）

| 論点 | 決め方 |
| ---- | ------ |
| U1: ブロックリストを、同じ Google アカウントでログインした別の端末の Chrome に同期するか | **決定: 同期しない**（範囲外に記載） |
| U2: 権限を持たないサイトが保存されたときの扱い | **決定: この機能ではブロックしない。** 権限はサイトごとのホスト権限のまま変えず、足したサイトの権限は #11 で追加時に求める（`block` ＋ 遷移の検知で全サイトを止める案は、警告が「全ページのブロック」「閲覧履歴の読み取り」に広がるため不採用） |
